# Journeys are transient by default, never auto-persisted

Le planificateur (F2) calcule un Journey pour chaque recherche, invité ou usager authentifié — mais rien n'est écrit en base automatiquement, même pour un compte connecté. Un Journey ne devient une ligne en base que si l'usager déclenche une sauvegarde explicite. On a considéré logger chaque recherche par défaut pour préparer l'historique/suivi carbone cumulé (v1.1), mais ces fonctionnalités ne sont pas MVP, la table grossirait sans lecteur, et ça soulève une question RGPD (minimisation) qu'on n'a pas besoin de trancher maintenant. Conséquence : le suivi carbone cumulé et un futur historique ne pourront pas être reconstruits rétroactivement sur les recherches passées — seuls les trajets explicitement sauvegardés à partir de leur implémentation compteront.
